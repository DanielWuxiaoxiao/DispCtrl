# X576 显控软件通信协议说明

适用对象：接口开发、联调和项目接收工程师。整理日期：2026-10-27。

依据：`x576` 分支、基础提交 `5efde26` 及整理时工作区代码。包含尚未提交的功能，不代表已经发布或完成现场验收。本文是当前实现的接口总览和关键字段说明；完整字段通过文末明细索引查阅，不能只拿总览表实现全部接口。

## 1. 先区分通信链路

软件同时支持多套协议，不能按相似名称混用报文。

| 链路 | 软件角色 | 传输 | 主要用途 | 配置位置 |
| --- | --- | --- | --- | --- |
| 雷达内部通信 | 显控端 | UDP | 控制、检测点、航迹、定位、设备状态 | `network.ips/ports/ids` |
| 电磁设备接口 | 接受控制并上报数据 | UDP | 编号1～9控制及上报 | `electromagnetic_device` |
| 总控接口 | 雷达设备端 | UDP组播＋单播 | 发现、登录、态势和装备状态 | `command_control` |
| 光电目指 | TCP服务端 | TCP | 单目标指示及响应 | `zhoushan_optical` |
| 光电V2 | 系统指控端 | UDP | 引导、设备控制、目标和状态 | `photoelectric_v2` |
| 9009激光接口 | 雷达端 | UDP | 侦察上报和状态 | `laser` |
| 边缘识别及MQTT | 上报端／识别结果接收端 | UDP JSON／MQTT | 目标与识别结果交换 | `network.edge_*`、`network.total_control_mqtt` |

光电目指、光电V2和9009误同时开启时，软件按“光电目指 > 光电V2 > 9009”选择一种。电磁和总控是独立功能。启用哪套接口，以实际加载的配置及启动日志为准。

## 2. 雷达内部协议

### 2.1 公共帧

小端整数、IEEE754浮点、1字节对齐。下面偏移从0开始，`B`为业务结构长度，包含2字节消息号。

| 完整帧偏移 | 字段 | 类型／长度 | 含义 |
| ---: | --- | --- | --- |
| 0 | head | uint32／4 | `0xFA55FA55`，在线字节 `55 FA 55 FA` |
| 4 | srcID | uint16／2 | 源设备 |
| 6 | destID | uint16／2 | 目的设备 |
| 8 | commCount | uint32／4 | 通信计数 |
| 12 | dataLen | uint16／2 | `14+B`，从帧起始到业务末尾 |
| 14 | mesID及业务字段 | B | 按具体消息结构 |
| dataLen | checkCode | uint8／1 | 偏移0至dataLen-1逐字节异或 |
| dataLen+1 | end | uint32／4 | `0x55FA55FA`，在线字节 `FA 55 FA 55` |

总长为 `dataLen+5=19+B`。依据为 `Basic/Protocol.cpp::packData()`，不是旧文档中“长度只含消息号与内容”的写法。

当前通用接收入口 `ThreadedUdpSocket::validateFrame()`只统一检查最小长度和头尾；部分后续分支另做结构长度检查。不能把它写成“所有消息都已严格校验长度、ID和XOR”。对接发送端仍应生成完整正确帧。

### 2.2 设备编号和端口

编号：资源调度BB01、信号处理BB02、数据处理BB03、显控BB04、目标识别BB05、监控BB06。以下是当前仓库配置的端口，部署时以现场配置覆盖；IP不固化为接口契约。

| 数据方向 | 源端口 → 目的端口 | 主要消息 |
| --- | --- | --- |
| 显控 → 资源调度 | 6012 → 8012 | AA01～AA07 |
| 显控 → 信号处理 | 6002 → 8002 | CC01～CC03 |
| 信号处理 → 显控 | 6003 → 8003 | DD01检测点 |
| 信号处理 → 显控 | 6004 → 8004 | DD02～DD05等 |
| 数据处理 → 显控 | 6006 → 8006 | EE01普通航迹 |
| 数据处理 → 显控 | 6010 → 8010 | EE02 TBD航迹 |
| 数据处理 → 显控 | 6020 → 8020 | EE03协同航迹 |
| 显控 → 数据处理 | 6008 → 8008 | DF01手动跟踪、DF02道路点 |
| 目标识别 → 显控 | 6017 → 8017 | DB01 |
| 显控 → 监控 | 6018 → 8018 | DA01软件启停 |
| 监控 → 显控 | 6019 → 8019 | CF01软件状态 |

普通检测／航迹路由会核对来源端口，不可只改目的端口。TBD和协同分支存在不同程度的端口容错；新对接仍须按配置使用固定源、目的端口。BIT/伺服回送还受接收分支影响，现场以抓包核对实际入口。

### 2.3 消息和操作对应

| 消息号 | 内容 | 说明 |
| --- | --- | --- |
| AA01 | 阵面开启控制 | 四个阵面分别开关；初始显示阵面数不等于启动时自动下发 |
| AA02 | 接收／发射 | 开关字段0/1 |
| AA03 | 伺服 | 停转0、转动1、寻位2、归北3；角度0.01°、速度秒/转 |
| AA04 | 工作模式 | TWS=0、TAS=1；当前待机操作另发送2 |
| AA05 | 波形采样 | 频点、方位、场景、三组波形与采样参数 |
| AA06 | 信号处理 | 门限、算法、距离上限和高度下界 |
| AA07 | 数据处理 | 航迹起始、终止和关联门限等 |
| CC01／02／03 | 保存／删除／离线处理 | DD02／03／04返回相应状态 |
| DD01 | 检测点 | 消息号＋512B控制表＋阵面ID＋数量＋N×detInfo |
| DD05 | 雷达经纬高 | GeoLocationReport |
| EE01／02／03 | 普通／TBD／协同航迹 | TrackResult＋N×trackInfo；分开管理 |
| DE01／DE02 | 伺服回送／BIT | BIT业务结构39字节，含消息号 |
| DB01／CF01 | 分类／软件状态 | 状态来源与网络连通状态分开 |
| EE10／EE11 | A显／波束调度 | 扩展显示入口，详见结构定义和对应Manager |

AA06、AA07当前通过 `Controller → Disp2ResManager` 发送，不要仅按功能名称改投信处或数处端口。通用下发日志表示请求已提交，不能当作硬件执行成功。

### 2.4 AA05当前结构：54字节

下表偏移相对于业务结构起点，即完整帧偏移14处。

| 偏移 | 字段 | 类型 | 单位／含义 |
| ---: | --- | --- | --- |
| 0 | mesID | uint16 | AA05 |
| 2 | freqID | uint8 | 0/10/…/80对应9.0/9.1/…/9.8GHz；TAS随机跳频90（5A） |
| 3 | type | uint8 | 1负调频、2正调频 |
| 4、8 | aziStart、aziEnd | 各int32 | 0.01° |
| 12 | aziStep | int16 | 0.01° |
| 14 | scene | uint8 | 当前对话框显示序号=原始值+1 |
| 15 | flagNum | uint8 | 生效波形数 |
| 16 | pulseNum | uint16 | 三组共用的积累脉冲数 |
| 18、30、42 | 三组波形起点 | 各12字节 | 见下文 |

每组依次为：使能uint8、波形码uint8、采样起始uint16、采样终止uint16、俯仰起始int16、俯仰终止int16、俯仰间隔int16。采样量化0.1μs，俯仰量化0.01°。

旧明细中的方位short、每组独立脉冲数及53字节排布与当前结构不同。新接收端须使用当前54字节布局，并与设备端抓包会签。随机跳频只新增于TAS，仍需设备端支持90编码。

### 2.5 AA06新增字段

AA06业务结构固定32字节。相对业务起点偏移22～23为距离处理上限uint16，偏移24～25为高度处理下界int16，均小端、1m量化；偏移26～31保留6字节。当前默认分别5200m和0m，高度下界允许负数。这是处理参数，不是显示量程或高度坐标修正。

### 2.6 点迹和航迹

DD01当前解析顺序为：消息号uint16、512字节控制表、阵面ID uint8、检测数量uint16、N条记录。完整帧总长为 `536+56N`。接收端实际按512字节跳过控制表，不应仅凭旧 `detResult/SigData` 结构名推断记录起点。

`detInfo` 每条56字节，依次为：dis、vel、azi、ele、altitute、amp、CFARSNR、statSNR、aziBeam、eleBeam（10个float），disChannel、dopChannel（2个uint32），targetConfidence（float）、targetRecResult（uint32）。不能按航迹4字节头跳过。

三类航迹业务头均为 `mesID:uint16 + trackNum:uint16`，每条61字节；完整帧总长为 `23+61N`。

| 记录内偏移 | 内容 | 类型 |
| ---: | --- | --- |
| 0、2 | 批号、CPIID | 各uint16 |
| 4、8 | UTCtime、nsecond | 各uint32 |
| 12 | statMethod | uint8；0滤波、1外推、2消批 |
| 13、17 | amp、SNR | 各float |
| 21、25、29 | dis、azi、ele | 各float；m、度、度 |
| 33、37 | altitute、vel | 各float；m、m/s |
| 41、45 | spaceVel、accelerate | 各float |
| 49 | targetRecResult | uint32 |
| 53、57 | 两个预留字段 | 各uint32 |

当前DBT/TBD解析直接把azi/ele作为度，不再乘180/π。旧“58字节航迹”及“弧度”说明不能用于当前对接；如设备仍输出弧度，必须先统一双方单位。检测点公开分发前还校验有限数、距离0～1000km、方位[0,360)、俯仰±90°。

### 2.7 定位与BIT

DD05业务结构为消息号uint16、纬度int64、经度int64、海拔int32，共22字节；经纬度量化1e-9°，海拔0.01m。注意先纬度后经度。完整帧41字节。

DE02业务结构39字节：消息号2、BIT组1、电源状态1、FPGA温度2、阵面温度2、偏航2、子阵位图5、扫描角2、阵面ID1、预留21。温度0.1℃，角度0.01°；阵面ID为0～3。BIT组bit7发射开启、bit6占空比报警、bit5脉宽报警、bit4接收开启、bit3频率源正常、bit2数字收发建链、bit1伺服正常、bit0北斗正常。报警位为1和正常位为1的含义不同，不能按全部1表示健康。

子阵电源bit0～35对应36个子阵；扫描角为绝对角，显示时不再加偏航。完整DE02帧58字节。

## 3. 电磁设备接口

独立UDP端点，当前配置端口为显控8022、设备6022；设备ID由本节配置读取。公共帧同样14字节头＋消息号＋内容＋5字节尾，长度为16＋内容长度，采用XOR；不要将内部DD01记录原样当作编号5记录。

| 编号 | 方向 | 内容 |
| ---: | --- | --- |
| 1 | 设备→显控 | 电源状态1字节 |
| 2 | 设备→显控 | 接收、发射各1字节 |
| 3 | 设备→显控 | 模式1字节 |
| 4 | 设备→显控 | 场景1字节，范围1～5 |
| 5 | 显控→设备 | 检测点记录，每条64字节 |
| 6 | 显控→设备 | 航迹记录，每条61字节 |
| 7 | 显控→设备 | 阵面0状态15字节，不含阵面ID |
| 8 | 设备→显控 | 软件启停1字节，0关闭／1启动 |
| 9 | 显控→设备 | 四项软件状态各1字节 |

编号5／6的内容均先放数量uint16再放记录，因此完整帧分别为 `23+64N`、`23+61N`。电磁检测记录把高度改为int32米并追加经纬度int32（1e-7°）；电磁航迹记录把高度改为int32米，末尾8字节由预留改为经纬度int32（1e-7°）。两者不能直接memcpy内部结构。

单包上限1472字节。自动目标上报与上报许可独立：当前自动检测点和航迹默认关闭，可手动选择。状态7/9默认每秒上报，未收到实测状态时可发送默认值，收到后使用缓存；默认值不能证明设备正常。

本链路有独立手动经纬高，优先于原始DD05和配置备用；不是通用雷达位置覆盖。关闭自动航迹上报不会取消手动订阅。本机发送成功没有通用协议回执。

完整控制字段、记录格式：[显控协议](../显控协议.md)；运行行为：[电磁设备接入说明](../电磁设备接入说明.md)。代码以 `ElectromagneticDevice/deviceprotocol.*`、`devicemodule.*` 为准，旧说明中额外原点标签已从PPI移除。

## 4. 总控接口

使用 `CommandControl/`，与MQTT识别上报不是一套协议。公共头18字节，标识5AA5、版本10，小端；头部时间为北京时间当天起10ms计数。

| 类型 | 方向／方式 | 完整长度 | 用途 |
| --- | --- | ---: | --- |
| DD31 | 总控→显控／组播 | 36 | 发布ID、单播IP/端口和登录身份 |
| DD33 | 显控→总控／单播 | 38 | 登录或退出 |
| DD34 | 总控→显控／单播 | 24 | 登录结果 |
| DD25 | 显控→组播 | 23 | 链路检测 |
| DDA1 | 显控→组播 | 44 | 装备状态 |
| DDA4 | 显控→组播 | 67 | 航迹态势 |

默认组播224.0.1.2:21505，单播端点由DD31负载发现。操作目标上报前须本机UDP就绪、登录成功、普通航迹有效；F7与右键使用同一路径。不能把DD25正常或Ping成功当作登录完成。授时失败不阻止通信。

完整字段、量化和登录流程：[总控通信协议](../command_control_protocol.md)。实现入口：`commandcontrolprotocol.h`、`commandcontrolmodule.cpp`。

## 5. 三种光电链路

### 5.1 光电目指（TCP）

显控监听、光电主动连接；配置键 `zhoushan_optical`，默认端口9010，实际需双方确认。仅实现目标指示与响应，不包括设备控制、侦察和心跳。

帧头EB 90、帧尾4C 5A。请求类型在线04 00，响应04 01，均48字节；偏移及长度：头18＋内容26＋校验2＋尾2。

| 完整帧偏移 | 字段 |
| ---: | --- |
| 2 | 类型2字节 |
| 4、6 | 发送／接收ID各uint16 |
| 8 | 日期时间8字节 |
| 16 | 内容长度uint16=26 |
| 18 | 指示类型uint8：1提示、2确认 |
| 19 | 目标批号uint32 |
| 23 | 请求设备类型／响应结果uint8 |
| 24、32 | 经度／纬度double，度 |
| 40 | 海拔float，m |
| 44 | 校验uint16 |

校验对偏移2～43的小端uint16字逐字累加取低16位，不能用9009逐字节累加代替。类型1持续发送最新点且只保留一条待响应，类型2每次人工选择只发一次。同时选择一个普通航迹；停止仅停止后续发送，没有线上撤销帧。

响应匹配会话、批号、类型、时间，提示还匹配回显坐标。协议无请求流水号，同批次重复确认存在迟到响应歧义。完整响应枚举及边界：[光电目指接入说明](../舟山光电目指接入说明.md)，代码 `ZhoushanOptical/protocol.h`。

### 5.2 光电V2（UDP）

小端，版本1、帧头7D6D5D4C，长度为完整帧长，校验为校验字前全部字节相加取低8位。

| 功能 | 方向 | 总长度 |
| --- | --- | ---: |
| 3400引导 | 显控→光电 | 47 |
| 3500控制 | 显控→光电 | 34 |
| 3200目标 | 光电→显控 | 60 |
| 3000状态 | 光电→显控 | 43 |
| 3100终端心跳 | 终端→显控 | 22 |

本机目标／状态接收默认10100／11100，控制源10101、目的21001。引导经纬度uint32量化1e-5°、高度uint16为海拔+500m；负经纬度不支持。没有控制应答，关闭窗口不自动发送运动停止。完整字段：[光电V2接入说明](../光电V2接入说明.md)，代码 `PhotoelectricV2/protocol.h`。

### 5.3 9009及旧光电

9009公共头18字节、尾4字节，EB 90／4C 5A。状态类型0002，侦察0003；校验为类型到内容末尾逐字节累加低16位。侦察内容为12＋64N字节，最多10目标，完整长34＋64N。状态按周期发送，侦察由真实普通航迹新点触发。

旧10100光电引导和V2有同名3400，但旧长度含义及实现与V2不同，不允许按功能号互换。旧明细中关于XOR、心跳、示例IP的文字应对照当前发送代码，当前 `checkAccusation()` 是低8位累加。参见[旧光电与激光协议](../光电跟踪与激光上报协议.md)、`UDP/threadudpsocket.cpp`及`Controller/laserreportmanager.cpp`。

## 6. 其他接口及联调顺序

边缘终端UDP JSON发送端口默认9001，回传识别结果监听9002；MQTT为3.1.1、QoS0、不保留，默认主题 `x576/target/result`。按track_id关联radar和optical，两者可能为空，软件不做融合判决。见[MQTT字段说明](../total_control_mqtt_protocol.md)。旧GCS二进制52上报有独立开关，不等于总控DDA4。

外部雷控 `ExternalCtrlManager` 保留512B系统控制、64B回执、32B伺服控制／回执；它是透传接口，不能当成已经实现完整业务控制。见[外部接口说明](../external_protocol_notes.md)。

联调按以下顺序进行：

1. 确认双方版本、工作区／发布包、实际配置路径及协议种类。
2. 确认本机网卡、固定源／目的端口、组播或TCP角色和设备ID。
3. 对照总长、字节序、校验、坐标量化，先收一条黄金样本。
4. 验证单目标正常更新、外推、消批，再验证多目标和断线恢复。
5. 同时记录本机发送、对端接收和应用响应，分清三个阶段。

当前材料未执行设备抓包或完整运行验收。尤其应会签：内部长度字段、AA04长度3字节、AA05长度54字节、航迹61字节与角度单位、TAS频点90，以及各光电校验方式。
