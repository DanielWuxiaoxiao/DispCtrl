# X576 显控软件代码架构与部署说明

适用对象：项目接收、维护和部署工程师。整理日期：2026-10-27。

依据为 `x576` 分支基础提交 `5efde26` 及整理时工作区。当前存在未提交代码，正式移交时应同时提供最终提交号、安装包及对应配置。本文与[通信协议说明](01_通信协议说明.md)、[客户使用手册](03_客户使用手册.md)配套。

## 1. 软件负责什么

软件负责接收雷达检测点、航迹和设备状态，显示P显、B显、高显、3D视图，向处理分系统发送控制参数，并按配置接入总控、光电和电磁设备。雷达信号处理与航迹生成主要由外部分系统完成，不能把显控当作完整雷达算法后端。

主要技术为Qt5、C++17、QGraphicsView和Qt WebEngine。Windows工程使用Qt5.14系列；Linux发布脚本有独立Qt5.15.2兼容基线。

## 2. 数据如何流动

```text
雷达UDP报文 → ThreadedUdpSocket → 对应Manager → Controller信号
                                               ├→ PPI／B显／高显／表格
                                               ├→ 3D模型 → WebChannel → Three.js
                                               └→ 启用的外部设备模块

操作员按钮 → 参数对话框 → Controller → 发送Manager → UDP → 处理分系统

外部设备报文 → 各自独立的UDP／TCP模块 → 状态模型 → 操作窗口／健康管理
```

Controller是分发中心，不在绘图对象里直接创建设备通信。普通航迹、TBD和协同航迹使用独立类型／入口，批号相同也不能合并为同一目标。

### 2.2 线程与对象所有权

GUI、QWidget、场景和图元只在GUI线程操作。内部套接字通过moveToThread进入工作线程；普通航迹当前在接收线程解码，再通过排队调用交给GUI侧批量分发。各外部模块有独立收发线程、缓存和在途控制，应沿用模块现有连接方式。

Qt对象使用parent管理；跨线程对象通常在工作线程结束时deleteLater。QGraphicsItem的场景归属和移除／删除需成对处理。跨线程传输传值或显式拥有的缓冲，不把马上释放的裸指针交给排队任务。

新接入请依次检查：创建线程 → 连接类型 → 缓冲所有权 → 消费线程 → 退出顺序。修改位置参考信息时，还应检查Controller转发到地图和外部模块的所有订阅者。

### 2.3 显示性能约束

P显检测点为批量图元；航迹历史按批绘制，仅最新点保留交互锚点。B显／高显也使用批量图元。重绘请求约16ms合并，表格和标签另行批量／限频更新。

不得恢复逐点创建场景图元、逐点全表刷新或无限日志。优先保持现有FIFO与有界缓存：`max_points`、`max_track_points`、标签刷新间隔等。发现卡顿时先采样GUI线程和绘制栈，再判断是文本、图元、日志、网络交付还是WebEngine；源码静态推断不能代替性能实测。

## 3. 三个容易接错的业务边界

### 3.1 位置与姿态

通用参考模型按字段选择“UI手动值 > 最近有效设备上报 > 开机默认值”，0是有效值。通用窗口“确定”仅本次运行，“保存本地”写入实际加载TOML的radar段。通用UI高度限制-1000～5000m，设备上报范围另行校验。

电磁启用时，左上角按钮打开电磁原有专用窗口；它保留独立手动原点，使用原始DD05，不共享通用UI覆盖。该窗口只有经纬高和恢复自动，没有通用姿态保存功能。接收项目时必须分别验证两个分支，不能用历史“全部统一”说明覆盖当前隔离行为。

偏航／倾角用于显示和阵面方向，不额外旋转已经输入的目标RAE。阵面ID保持物理编号；阵面方向按第一阵面偏航加ID×90°，关闭中间阵面不重编号。BIT扫描角按绝对角使用，不能再叠加偏航。

### 3.2 参数与显示

TAS下发按AA04、AA05、AA03的现有信号顺序提交；频率90表示随机跳频。AA06高度下界、距离上限是设备处理参数；P显量程和B/H坐标范围是显示参数，不可混用。

所有结构以当前 `Protocol.h` 为准，旧文档中的AA04／AA05排布、航迹字节数和角度单位有历史差异，详见配套协议说明。

### 3.3 对外通信与状态

光电目指、V2、9009互斥启用；电磁、总控和MQTT分别开关。普通航迹公共信号可能含本地测试航迹；有数据不自动等于真实雷达数据。离线绘图和回放不得冒充实时普通航迹触发设备上报。

本机网卡正常、对端Ping可达、本机发送成功、协议接收有效、设备处理成功是不同状态。UI和测试应分别证明，不能统称“连接正常”。

## 4. 配置与现场布置

### 4.1 配置文件位置

主程序调用 `load("config.toml")`，相对路径从进程当前工作目录解析。ConfigManager保存绝对路径供后续写回。不是只要修改仓库根目录文件就一定生效。

CMake向输出目录复制配置时，已有文件通常保留，不覆盖现场参数。启动快捷方式应设置正确工作目录；查启动日志确认实际路径，然后修改该文件。

| 配置段 | 工程师需要核对的内容 |
| --- | --- |
| network | 内部双方IP、源／目的端口、ID |
| radar | 开机经纬高、偏航、倾角 |
| displayConfig | 1～4阵面显示、FIFO、TBD/协同、标签、扇区 |
| map／osm | 地图引擎、默认类型、道路资源与坐标转换 |
| command_control | 总控开关、网卡、组播、ID、登录和录制 |
| electromagnetic_device | 电磁开关、端点、许可与自动上报 |
| laser／photoelectric_v2／zhoushan_optical | 选定光电协议和端点 |
| logging／webengine／ui | 日志限频、图形后端、DPI策略 |

仓库目前启用了部分电磁、测试数据和识别接收功能，不能把开发配置原样视为客户交付配置。交付前由现场清单明确每项开关，不在文档中复制真实站点坐标、口令或内部网段。

### 4.2 部署拓扑

```text
显控PC
 ├─ 雷达数据网：信处／数处／资调／监控
 ├─ 外部业务网：选定的光电、总控或电磁端点
 └─ 本地资源：程序、Qt运行库、config.toml、地图／道路及日志目录
```

每个配置本机IP必须实际存在于本机网卡。多网卡时核对路由、组播网卡和防火墙，不使用随意改成0.0.0.0的方法掩盖错误。TCP目指由显控监听，光电主动连接；UDP按协议固定源和目的端口。

## 5. 构建与发布

### 5.1 Windows

准备64位Qt5、匹配的MSVC工具链、CMake和构建工具。必需Qt模块为Core、Gui、Widgets、Network、WebEngineWidgets、WebChannel；QTest目标另外需要Test。不要混用不同架构或编译器的Qt包。

以下是工程师按需执行的示例，本文整理过程中没有运行构建：

```powershell
# 在VS x64开发环境中执行；Qt路径替换为实际安装位置
cmake -S . -B build -DCMAKE_PREFIX_PATH="<Qt安装目录>"
cmake --build build --config Release
```

若复用已有build目录，应保持其生成器和工具链。默认输出通常在 `build/bin/Release`，以实际生成结果为准。可选qmake入口为 `DispCtrl.pro`。新增源码／头文件同步维护CMake和qmake，避免一套环境能编译、另一套漏MOC。

发布时随包提供所需Qt运行库、platforms和WebEngine资源／子进程等；不要只拷贝exe。图标和网页中由resource.qrc内嵌的部分无需再复制源码资源清单，但外置配置和地图数据需要随包检查。具体依赖由本机Qt部署工具和目标机验证确定。

### 5.2 Ubuntu

已有正式脚本，不把Windows exe转换成Linux程序。Windows＋WSL＋Docker入口：

```powershell
.\docker\build_ubuntu.ps1 -Target 1804 -CheckOnly
.\docker\build_ubuntu.ps1 -Target 1804 -Jobs 4
```

1804／2004采用兼容基线；2204／2404包不能承诺在更老系统运行。包通常输出至 `deploy/ubuntu1804/`，含压缩包、SHA256、BUILD-INFO和启动／检查脚本。目标机用日常用户安装，按包内说明安装离线依赖，然后执行check_package.sh与run.sh。详见[Ubuntu发布说明](../Ubuntu发布说明.md)。

## 6. 接收工程师最小验收

1. 记录最终提交、未提交差异、工具链、发布包SHA256及BUILD-INFO。
2. 备份现场配置，核对加载路径、网卡、端口和外设开关。
3. 编译并选择运行相关QTest：位置参考、TAS编码、协议、模块生命周期、窗口几何、开关互斥。
4. 验证检测点、普通航迹、消批和BIT；TBD／协同按交付范围启用并分别验收。
5. 验证参数保存与重启回读，抓AA04／AA05／AA06关键字节并核对设备回送。
6. 验证P/B/H/3D、地图切换、扩展屏最大化／还原、分离／重附加。
7. 每个外设做正常、断线、恢复、切换目标和停止测试；保存双方报文与响应。
8. 做持续运行和目标负载测试，观察CPU、内存、GUI延迟和日志增长。

WebEngine页面必须兼容Qt5.14的Chromium77。不能只看到WebChannel连接就认定3D正常，还要检查canvas尺寸、实际首帧和恢复行为。
