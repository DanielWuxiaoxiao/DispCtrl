## 1. 基本约定

- 传输协议：UDP。
- 数据格式：定长/变长二进制报文
- 字节序：小端（Little-Endian）。
- 结构体按 1 字节对齐，不允许编译器自动填充。
- 一个 UDP 数据报对应一个完整协议帧。
- 经纬度使用 WGS84 坐标系
- IP 地址、端口和双方设备 ID 使用[第 7 节](#integration-parameters)的定版值

<a id="common-frame"></a>

## 2. 公共协议帧

所有报文均使用以下帧格式：

| 字段 | 长度 | 类型 | 说明 |
| --- | ---: | --- | --- |
| 帧头 | 4 | `uint32` | 固定值 `0xFA55FA55` |
| 源设备 ID | 2 | `uint16` | 发送方设备 ID |
| 目的设备 ID | 2 | `uint16` | 接收方设备 ID |
| 通信计数 | 4 | `uint32` | 发送方递增计数，溢出后从 0 开始 |
| 数据长度 | 2 | `uint16` | 从帧头开始到业务数据结束的长度，不含校验码和帧尾 |
| 信息编号 | 2 | `uint16` | 见第 3 节 |
| 信息内容 | 可变 | - | 对应信息编号的业务数据 |
| 校验码 | 1 | `uint8` | 对前述帧头至信息内容逐字节异或 |
| 帧尾 | 4 | `uint32` | 固定值 `0x55FA55FA` |

长度计算：

```text
数据长度 = 14（帧头至数据长度字段） + 2（信息编号） + 信息内容长度
UDP 报文长度 = 数据长度 + 1（校验码） + 4（帧尾）
```

接收端至少检查帧头、帧尾、数据长度、校验码和信息编号。检查失败的报文直接丢弃并记录日志。


<a id="message-ids"></a>

## 3. 信息编号

编号从 `1` 重新开始，仅包含本次对接所需功能：

| 编号 | 方向 | 功能 |
| ---: | --- | --- |
| `1` | 合作方 → 本端显控 | 阵面电源控制 |
| `2` | 合作方 → 本端显控 | 收发控制 |
| `3` | 合作方 → 本端显控 | 工作模式控制 |
| `4` | 合作方 → 本端显控 | 场景设置 |
| `5` | 本端显控 → 合作方 | 检测点上报 |
| `6` | 本端显控 → 合作方 | 航迹上报 |
| `7` | 本端显控 → 合作方 | 阵面状态上报 |
| `8` | 合作方 → 本端显控 | 软件启动/关闭 |
| `9` | 本端显控 → 合作方 | 软件状态上报 |

目标识别结果不单独定义报文，包含在检测点和航迹记录的识别字段中。

<a id="partner-commands"></a>

## 4. 合作方下发

信息编号后紧跟业务字段，所有字段均按小端序排列。

### 4.1 阵面电源控制

信息编号：`1`，业务内容长度：1 字节。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 电源状态 | `uint8` | `0` 关闭，`1` 开启 |

### 4.2 收发控制

信息编号：`2`，业务内容长度：2 字节。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 接收状态 | `uint8` | `0` 关闭，`1` 开启 |
| 发射状态 | `uint8` | `0` 关闭，`1` 开启 |

### 4.3 工作模式控制

信息编号：`3`，业务内容长度：1 字节。

| 值 | 模式 |
| ---: | --- |
| `0` | TWS |
| `1` | TAS |

### 4.4 场景设置

信息编号：`4`，业务内容长度：1 字节。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 场景编号 | `uint8` | 取值 `1~5`，对应显控界面的场景编号 |

### 4.5 软件启动/关闭

信息编号：`8`，业务内容长度：1 字节。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 软件状态 | `uint8` | `0` 关闭，`1` 启动 |

## 5. 本端显控上报

<a id="detection-report"></a>

### 5.1 检测点上报

信息编号：`5`。

```text
信息编号 uint16
检测点数量 uint16
检测点记录 × N
```

单条检测点记录固定 64 字节：

| 顺序 | 字段 | 类型 | 单位/说明 |
| ---: | --- | --- | --- |
| 1 | 距离 | `float` | m，斜距 |
| 2 | 速度 | `float` | m/s |
| 3 | 方位 | `float` | 度，正北为 0°，顺时针增加 |
| 4 | 俯仰 | `float` | 度，水平为 0°，向上为正 |
| 5 | WGS84 高度 | `int32` | 分辨率 `1 m`
| 6 | 幅度 | `float` | dB |
| 7 | CFAR 信噪比 | `float` | dB |
| 8 | 统计信噪比 | `float` | dB |
| 9 | 方位波束指向 | `float` | 度 |
| 10 | 俯仰波束指向 | `float` | 度 |
| 11 | 距离通道 | `uint32` | - |
| 12 | 多普勒通道 | `uint32` | - |
| 13 | 目标置信度 | `float` | `0.0~1.0` |
| 14 | 目标识别结果 | `uint32` | `0` 其它，`1` 无人机 |
| 15 | 经度 | `int32` | WGS84，经度 × `1e7`，东经为正 |
| 16 | 纬度 | `int32` | WGS84，纬度 × `1e7`，北纬为正 |

无检测点时，检测点数量为 `0`。

<a id="track-report"></a>

### 5.2 航迹上报

信息编号：`6`。

```text
信息编号 uint16
航迹数量 uint16
航迹记录 × N
```

单条航迹记录固定 61 字节：

| 顺序 | 字段 | 类型 | 单位/说明 |
| ---: | --- | --- | --- |
| 1 | 航迹批号 | `uint16` | 目标关联编号 |
| 2 | CPI 编号 | `uint16` | - |
| 3 | UTC 时间 | `uint32` | - |
| 4 | 子秒时间 | `uint32` | - |
| 5 | 状态估计方式 | `uint8` | `0` 滤波，`1` 预测，`2` 删除 |
| 6 | 幅度 | `float` | - |
| 7 | 信噪比 | `float` | dB |
| 8 | 距离 | `float` | m，斜距 |
| 9 | 方位 | `float` | 度 |
| 10 | 俯仰 | `float` | 度 |
| 11 | WGS84 高度 | `int32` | 分辨率 `1 m`
| 12 | 径向速度 | `float` | m/s |
| 13 | 空间速度 | `float` | m/s |
| 14 | 加速度 | `float` | m/s² |
| 15 | 目标识别结果 | `uint32` | `0` 其它，`1` 无人机 |
| 16 | 经度 | `int32` | WGS84，经度 × `1e7`，东经为正 |
| 17 | 纬度 | `int32` | WGS84，纬度 × `1e7`，北纬为正 |

无航迹时，航迹数量为 `0`。识别结果通过本记录的“目标识别结果”字段获取，不另发报文。原记录末尾 8 字节预留区改为经度和纬度，因此单条航迹记录仍为 61 字节。`状态估计方式=2` 的消批记录仍须发送；正常情况下复用该批次最后一个有效点的距离、方位、俯仰和经纬高，接收方以航迹批号和状态估计方式执行删除。

### 5.4 阵面状态上报

信息编号：`7`，本版默认对应阵面 `0`，不再携带阵面 ID。

业务字段按以下顺序排列，业务内容长度为 15 字节：

| 顺序 | 字段 | 类型 | 单位/说明 |
| ---: | --- | --- | --- |
| 1 | BIT 状态组 | `uint8` | bit7 发射开启；bit6 占空比报警；bit5 脉宽报警；bit4 接收开启；bit3 频率源正常；bit2 收发链路正常；bit1 伺服正常；bit0 北斗正常 |
| 2 | 电源状态 | `uint8` | bit0 波控板电源正常 |
| 3 | FPGA 温度 | `uint16` | 实际值 = 字段值 / 10，单位 °C |
| 4 | 阵面温度 | `uint16` | 实际值 = 字段值 / 10，单位 °C |
| 5 | 阵面偏航角 | `uint16` | 实际值 = 字段值 / 100，单位 ° |
| 6 | 子阵电源状态 | `uint8[5]` | 子阵电源 BIT |
| 7 | 当前扫描角 | `uint16` | 实际值 = 字段值 / 100，单位 ° |

<a id="software-status-report"></a>

### 5.5 软件状态上报

信息编号：`9`，业务内容长度：4 字节。

| 顺序 | 字段 | 类型 | 说明 |
| ---: | --- | --- | --- |
| 1 | 数据处理软件状态 | `uint8` | 状态值见下表 |
| 2 | 波束调度软件状态 | `uint8` | 状态值见下表 |
| 3 | 信号处理软件状态 | `uint8` | 状态值见下表 |
| 4 | 目标识别软件状态 | `uint8` | 状态值见下表 |

| 值 | 含义 |
| ---: | --- |
| `0` | 正常 |
| `1` | 异常 |
| `2` | 启动成功 |
| `3` | 启动失败 |

软件状态上报与显控UI状态模型一致：软件启动初始四项均为`1`（异常）；UI状态`0~3`原值上报，UI扩展状态`4`（关闭成功）与`5`（关闭失败）均映射为`1`。线上值域仍为`0~3`，不增加新状态码。

<a id="receiver-requirements"></a>

## 6. 接收端要求

1. 按小端序、1 字节对齐解析，不使用 C/C++ 默认结构体填充。
2. 校验帧头、帧尾、数据长度、信息编号和异或校验码。
3. 校验失败或字段越界时丢弃报文并记录日志。
4. 使用公共帧中的通信计数判断重复或乱序；UDP 丢包不要求重传。
5. 一个 UDP 报文不超过 1472 字节。计入公共帧、数量字段、校验码和帧尾后，单包最多发送 22 条检测点记录或 23 条航迹记录；超过时按同一信息编号分包，每包使用独立通信计数和实际记录数量。
6. 本协议不定义通用应答；控制执行结果通过后续状态上报体现。

<a id="integration-parameters"></a>

## 7. 联调参数

本协议使用 `192.168.64.0/24` 网段，子网掩码为 `255.255.255.0`。双方均使用固定监听端口，发送报文时也从本方固定监听端口发出，不使用临时源端口。

| 设备 | IP 地址 | UDP 端口 | 设备 ID | 说明 |
| --- | --- | ---: | ---: | --- |
| 本端显控 | `192.168.64.4` | `8022` | `0xBB04` | 复用工程既有显控设备 ID |
| 合作方显控 | `192.168.64.8` | `6022` | `0xBB08` | 本协议专用，避开工程既有 `0xBB01~0xBB07` |

| 报文方向 | UDP 源 | UDP 目的 | 帧内源设备 ID | 帧内目的设备 ID |
| --- | --- | --- | ---: | ---: |
| 合作方 → 本端显控（信息编号 `1/2/3/4/8`） | `192.168.64.8:6022` | `192.168.64.4:8022` | `0xBB08` | `0xBB04` |
| 本端显控 → 合作方（信息编号 `5/6/7/9`） | `192.168.64.4:8022` | `192.168.64.8:6022` | `0xBB04` | `0xBB08` |

设备 ID 按 `uint16` 小端写入：`0xBB04` 的线上字节为 `04 BB`，`0xBB08` 的线上字节为 `08 BB`。阵面 ID 固定为 `0`，不在报文中携带。
