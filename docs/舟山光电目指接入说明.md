# 舟山光电目标指示接入

仅实现用户指定的《舟山光电》第6节：6.1目标指示发送、6.2目标指示响应接收。**不发送第5节侦察数据，不实现第3节设备控制或第4节状态/心跳。** 代码位于`ZhoushanOptical/`，协议和运行状态独立于9009激光及10100光电V2。

## 配置与连接

修改实际加载的`config.toml`后重启：

```toml
[laser]
enabled = false
[photoelectric_v2]
enabled = false
[zhoushan_optical]
enabled = true
local_ip = "192.168.101.14"
peer_ip = "192.168.101.10"
listen_port = 9010
sender_id = 1100
receiver_id = 3101
indication_type = 1
```

按文档“指控TCP服务端、光电TCP客户端”，显控监听`local_ip:listen_port`，光电主动连接该地址；仅接受`peer_ip`的一个活动连接，不限制其临时源端口。IP、TCP端口及双方ID均可配置。9010是文档未指定端口下的独立默认值，须通知合作方，不复用9009或10100。绑定错误明确显示，不偷偷监听所有网卡或回退其它协议。

三种协议误同时开启时告警并按“舟山→V2→9009”确定唯一活动协议，低优先级不创建收发模块，也不显示其健康页IP状态。旧`system.enable_photoelectric_tx`在舟山或V2启用时隔离。默认舟山关闭，原有9009默认值不变。

## 操作和状态

- PPI“光电(F6)”输入普通航迹批号下发；普通航迹点/标签右键下发、停止。**同时只选中一个目标**：F6/右键成功切换新批次即停止旧批次后续下发；消批、过期或手动停止也停止发送。断线期间仍可右键停止已选目标，防止重连续发。可以使用既有测试航迹，前提是TCP已连接且雷达原点有效。UI使用中性名称“光电”，仅配置段`[zhoushan_optical]`及内部诊断标识区分协议。
- `indication_type=1`：持续目标提示。每次只保留一条待响应请求；收到响应或超时后，按`report_interval_ms`发送最新点，不积压历史坐标。协议没有消批/取消命令，停止和消批只停止本地下发，不能撤回已进入TCP的帧。
- `indication_type=2`：目标确认请求，每次人工下发仅发送一次；超时或断线后不自动重新要求操作员确认，需重新F6/右键下发。切换目标或停止不清除已在对端执行的操作。
- 健康页分别显示本机IP、对端ICMP、TCP连接和目指结果。PPI恢复“光电目指状态”按钮，与健康页状态条打开同一详情窗口，显示雷达侧监听端点、光电IP、TCP状态、当前下发批号及两栏回传：**当前批次、上一个不同批次**。切换批次时轮换，重复选择同批次不轮换；尚未回传明确显示等待，停止后保留最后结果。迟到的上批次回传仅更新上批次栏，未知批次及旧TCP会话不混入两栏；接收顺序号避免同毫秒乱序覆盖。每栏包括批号、指示类型、状态值及含义、经纬高、对端时标、本机接收时间、双方ID和请求匹配标记，仅保留两条最新结果，不累积历史。正文使用浅色字体，V2实际设备控制入口不受影响。没有请求时显示“未请求”，不因协议没有心跳而周期性误报接收超时。
- 提示响应区分“已接收并处理”和“已接收但忽略”；确认响应区分“不能确认/是目标/不是目标”。“本机TCP入队”不当作光电已执行。响应超时明确标识，未收到真实响应不显示默认成功。

### 操作窗口布局

窗口使用与健康管理一致的深色/青绿色主题，上方为TCP连接、当前下发状态、雷达地址和光电地址四张状态卡；连通绿、故障红、等待/超时黄。正文及表格22px、分区标题24px，不再向操作员展示“仅第6节”等开发说明。

下方表格按“信息项 / 最近下发 / 当前批次回传 / 上一批次回传”并列，包含批号、指示类型、处理状态、经纬高、报文时间、本机时间、双方ID和应答关联。最近下发只在工作线程确认写入本机TCP缓冲后更新，未确认的待发送请求不冒充已发送；接收栏保留真实状态值及中文解释，无数据用“尚未下发/等待回传/暂无回传”区分，不以零坐标假装目标。最近下发不等同对端执行成功。停止按钮无活动目标时禁用。

固定10×4单元格仅在值变化时更新，隐藏窗口不刷新表格，关闭重开保留有界数据模型。初始窗口尺寸按所在屏幕可用区域设置，避免通用分离窗口首次`adjustSize()`将其缩成小字窗口；小窗口支持滚动和手动调整列宽，字体不随窗口缩小。

## 报文口径

采用小端整数和IEEE754浮点，依据文档逐字节帧类型及附录Windows式校验代码实现；首次联调仍应以合作方抓包核对字节序。请求帧类型在线字节`04 00`，响应`04 01`，二者均48字节：公共头18＋内容26＋校验2＋帧尾2。

| 完整帧偏移 | 内容 | 字节 |
|---:|---|---:|
| 0 | EB 90 | 2 |
| 2 | 帧类型 | 2 |
| 4 / 6 | 发送ID / 接收ID | 各2 |
| 8 | 年月日时分秒各1＋毫秒2 | 8 |
| 16 | 内容长度26 | 2 |
| 18 | 指示/响应类型1或2 | 1 |
| 19 | 目标批号uint32 | 4 |
| 23 | 请求为设备类型1=雷达；响应为结果状态 | 1 |
| 24 / 32 | 经度/纬度double，度 | 各8 |
| 40 | 海拔float，米 | 4 |
| 44 | 16位字累加校验 | 2 |
| 46 | 4C 5A | 2 |

校验范围为偏移2～43，按小端uint16逐字累加取低16位，奇数尾字节补0。**不是9009现有模块的逐字节累加算法**。时标年份使用2000～2099的后两位；`time_basis=local/utc`由现场与对端统一，文档未规定时区。发送填有效高度，不使用文档拼写有歧义的无效高度；接收对高度位型`0x0FFFFFFF`和`0xFFFFFFFF`标注无效，其他NaN/无穷拒绝。

仅使用普通航迹`traInfoProcess`最新点。DD05优先于完整有效的`[radar]`经纬高备用，复用`Basic/wgs84coordinate.h`的RAE→ENU→WGS84；高度为原点海拔加RAE垂直分量，不额外叠加偏航/倾角/横滚，不借用电磁临时手动原点。检测点、TBD、协同和离线回放不进入该链路。

接收校验头尾、48B长度、时标、类型、双方ID、结果枚举与经纬高。响应须匹配当前TCP会话、批号、指示类型和接收时限；类型1还要求坐标原样回显（文档6.2要求），防止将之前位置的应答当作新请求成功。类型2允许光电返回修正后的坐标，仅展示，不反向修改雷达航迹或原点。此协议没有请求流水号，重新人工请求相同批号/类型时，无法彻底区分对端延迟的旧确认结果；不要把同一目标反复点选当作严格事务机制。

## 运行边界和日志

TCP套接字/监听器在工作线程创建与销毁；处理粘包、拆包和帧头跨读取边界。接收缓存8KiB、底层读取缓存64KiB、一次最多64步解析；不完整帧超过5秒断开等待重连。响应最多缓存32个最新键，100ms合并并只允许一批等待GUI确认；不会把每条高频报文直接排入GUI。普通航迹缓存由`max_tracks`限制，`track_timeout_ms`后停止过期目标。发送一条待响应，已有TCP缓冲未清空则拒绝追加新帧，不堆积旧坐标。切换/停止通过共享原子令牌使尚未执行的旧Qt队列发送任务失效，工作线程写入TCP前检查；已开始写入TCP的帧无法撤回。

`ZS-OPT`日志包含实际配置路径、端点/ID/时区、监听/连接、原点、人工选择/停止、发送HEX采样、响应解释/HEX、失配/校验错误和超时。同类周期日志由`log_interval_ms`限频。连接、应用响应和本机入队三个概念分开显示。

针对性测试源码：`zhoushan_optical_protocol_test`、`zhoushan_optical_module_test`、`optical_indication_ui_test`及扩展的`subsystem_feature_flags_test`，包含黄金字节、校验、响应枚举、拆/粘包、垃圾前缀、缓冲上限、会话/坐标匹配、单请求在途、单目标切换/最新坐标/消批/断线取消、旧排队任务失效、两批次回传轮换/迟到/顺序保护、窗口可读性、类型2禁止自动重发及三种协议互斥。按仓库规则不自动完整构建；实际TCP客户端接入、F6/右键和健康页需本机编译后联调。
