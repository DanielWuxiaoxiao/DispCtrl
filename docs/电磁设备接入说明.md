# 电磁设备模拟交互接入说明

本模块用于模拟设备联调，线上字段依据同目录《显控协议.md》（2026-09-24）。方向已确认：电磁设备下发编号 `1/2/3/4/8` 控制，显控上报编号 `5/6/7/9`。模块名称、配置、UDP 套接字、状态窗口均独立于指控和光电链路。

## 启用配置

`config.toml` 的 `[electromagnetic_device]` 独立控制本模块，修改后重启生效。

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| enabled | false | 总开关；关闭时不启动 UDP、网络检测或显示入口 |
| ui_enabled | true | 参数设置区入口与健康管理状态项 |
| local_ip / local_port | 192.168.64.4 / 8022 | 显控固定发送/接收端点 |
| peer_ip / peer_port | 192.168.64.8 / 6022 | 模拟设备固定发送/接收端点 |
| local_device_id / peer_device_id | 0xBB04 / 0xBB08 | 16 位设备 ID，可用带引号的十六进制值 |
| remote_control_enabled | true | 接受有效报文后是否执行控制 |
| report_detections / report_tracks | true / true | 检测点、普通航迹上报开关 |
| auto_report_detections / auto_report_tracks | false / false | 自动下发开关；默认由鼠标手动选择，不收到数据就全量上报 |
| report_status | true | 阵面 0 BIT 与软件状态上报 |
| flush_interval_ms | 50 | 合并待发更新的周期，允许 20..1000 ms |
| status_interval_ms | 1000 | 状态报文发送周期，允许 100..60000 ms |
| receive_timeout_ms | 15000 | 有效控制报文及本机数据源的超时显示阈值 |
| network_check_enabled | true | 独立异步网口和 ICMP 检测 |
| network_poll_interval_ms | 5000 | 网络检测周期，允许 1000..60000 ms |
| data_log_enabled | true | 自动/持续更新的目标字段采样日志；人工下发操作始终记录 |
| data_log_interval_ms | 1000 | 点迹、航迹各自的采样日志间隔，允许 500..60000 ms |
| log_summary_interval_ms | 5000 | 累计流量、队列与发送统计间隔，允许 1000..60000 ms |

通信窗口提供上报许可、检测点自动下发、航迹自动下发和接收控制开关，不写回配置文件。右键普通航迹/标签选择“下发电磁设备(持续)”，再选一次停止手动订阅；右键检测点选择“点迹下发电磁设备（单次）”。自动模式下发全部有效普通航迹/检测点，不复用指控或激光筛选条件。关闭自动航迹模式只停止自动订阅，手动订阅仍有效；关闭航迹上报许可暂停普通更新，但已选批次消批仍发送删除。恢复许可时补发当前手动/自动选中的最新点。

## UI 状态含义

参数设置区增加“电磁设备通信”，健康管理窗口增加独立“电磁设备”状态入口。通信窗口分别显示：

- 本机网口：配置 IP 所在网卡处于启用且链路运行状态。
- 电磁设备网络：从配置本机 IP 发起异步 Ping，连续三次失败置不可达。
- UDP：本机指定 IP 和固定端口绑定是否成功。
- 协议接收：最近是否收到通过设备 ID、长度、校验和字段验证的控制报文。
- 检测数据源、航迹数据源：公共点迹入口或本机 DD01、EE01 是否持续到达，包括测试生成和数量为 0 的有效帧；“有数据”不表示来自真实雷达。
- DD05 原点、发送/失败/拒绝/溢出计数及待发数量。

绿色网络状态和本机 UDP 发送成功均不能证明对端应用收到数据。本协议没有心跳或通用应答；对端不发送控制命令时，“协议接收”会显示未收到/超时，不能据此判定网络断开。编号7/9默认每1秒自动上报：某类从未收到真实状态时用其默认值，收到后持续使用最后有效值，不因15秒超时停发或回退。默认阵面状态15字节全0（电源/状态位关闭或未正常、温度/角度0、子阵位图0）；软件从主界面状态模型初始化，启动四项均1（异常），不采用MonitorParam结构体的全0默认值。后续仅由UI状态模型变更通知更新软件缓存：0～3原值发送，UI的4关闭成功/5关闭失败按约定映射为异常1，外部协议不扩展。默认占位不证明设备健康；日志 `STATUS_TX` 标明 DEFAULT、REAL_LATEST、REAL_CACHED_STALE，`STATUS_UI` 同时记录UI原值与线上映射值。不反向修改旧健康管理或指控状态。

## 控制映射

编号7的36路子阵电源位图使用阵面1的UI已确认模型：连续全零不足100帧时保留此前位图，第100帧确认故障后发送全零；正常或部分位图按UI规则立即更新。不受健康窗口是否打开、当前选中哪个阵面影响。仅替换36个有效位，其他BIT字段与高4个保留位不变。未确认/未上报仍用全零占位（现有协议不能表达UI的黄色“未上报”），不修改原始BIT和旧链路。

| 编号 | 模拟设备命令 | 既有显控入口 |
| --- | --- | --- |
| 1 | 电源 0/1 | AA01，修改阵面 0，保留其它阵面开关 |
| 2 | 接收与发射 0/1 | AA02，同步本机发射按钮状态 |
| 3 | 0=TWS / 1=TAS | AA04，同步工作/待机状态 |
| 4 | 场景 1..5 | AA05，仅修改已缓存参数的场景值，其它波形参数保持当前值 |
| 8 | 软件关闭/启动 | DA01，控制处理软件，不关闭显控进程 |

控制仅接受配置的对端 IP/源端口和设备 ID；错误、重复、乱序报文不执行。通信计数按 32 位循环序列比较；超过接收超时后允许对端从新计数重新开始。协议不含认证，应在模拟联调网络中使用。

## 数据与坐标

发送业务统一使用 `Controller::detInfoProcess` / `traInfoProcess` 的 `PointInfo`，与现有指控/激光共享入口，因此既有测试航迹可以手动或自动下发。`detectionFrameReady` / `normalTrackFrameReady` 只补充原始字段缓存，绝不直接触发发送，避免同一真实点重复上报。普通航迹保留 CPI、UTC/子秒、空间速度、加速度；检测点保留统计 SNR、波束指向和通道。原始字段不匹配或检测字段缓存已淘汰时拒绝发送，不将缺失实测字段伪造为零。`PointInfo` 布局不变，既有 DREC 录制/回放格式不变。当前检测和航迹方位/俯仰均为度。

检测记录为 64 字节，航迹记录为 61 字节；经纬高使用 `Basic/wgs84coordinate.h`，与 DDA4 共用有效 DD05 原点：

```text
east = range × cos(elevation) × sin(azimuth)
north = range × cos(elevation) × cos(azimuth)
up = range × sin(elevation)
latitude = radarLatitude + north / (6378137 × π / 180)
longitude = radarLongitude + east / (6378137 × cos(radarLatitude) × π / 180)
altitude = radarAltitude + up
```

角度先转换为弧度，不重复添加阵面偏航。经度、纬度乘 `1e7` 四舍五入，高度按米四舍五入，编码为小端 `int32`；不使用显示模型的 `altitute` 覆盖目标 WGS84 高度。真实数据必须有有效 DD05；生成器通过 `testPointGenerated` 显式登记合成字段和来源，然后才发公共点信号。只有登记且样本匹配的测试点允许使用 `[radar]` 临时原点，不凭批号猜测测试来源；真实原始帧会撤销同批号/同采样的测试标记，真实 DD05 始终优先。测试航迹批号应与现场批号隔离。TBD、协同和离线显示流不接入此模块。

测试点迹由 `[test_detection]` 配置启用“生成测试点迹”按钮，默认每 500 ms 注入 10 个样本，可独立停止，旧检测点仍按现有显示容量淘汰。检测点无航迹批号，不借用批号作为测试标记。测试航迹使用生成时 UTC/纳秒、CPI=0、空间速度=径向速度、加速度=0；固定 RAE 视线匀速模型保证这两个速度一致。测试检测点缺失的统计 SNR、波束和通道显式填 0，仅表示合成测试值。

航迹每批只保留最新点。收到消批时，仅对曾选中上报的批次复用最后有效点并将状态改为 2，再删除缓存和手动订阅；未选中的航迹不发送消批。识别结果编码为 1=无人机、其它结果=0；后到分类更新缓存，仅对当前手动/自动选中的批次补发。

UDP 工作线程独占套接字。GUI 合并更新最多保留 2048 个待发检测记录；溢出按计数丢弃并限频告警。航迹按 16 位批号覆盖，模型上限为 65536 个键；发送用循环批号游标避免低批号更新饿死高批号。一次最多 128 个数据报，仅允许一批在工作线程待发；检测单包最多 22 条，航迹单包最多 23 条，均小于 1472 字节。错误日志限频 5 秒，状态 UI 每 500 ms 刷新。

## 本机模拟联调

将本节 `enabled=true`，本机与设备 IP 均改为 `127.0.0.1`，端口保持 `8022`、`6022`。生成测试航迹/测试点迹后，右键手动下发，或在“电磁设备通信”开启对应自动下发。不开自动且不选择目标时不发送目标报文。真实数据联调需 DD01/EE01/DD05。

模拟端仅在显式指定 `--command` 时发控制，默认只收报文：

```powershell
python scripts/electromagnetic_device_simulator.py --self-test
python scripts/electromagnetic_device_simulator.py --duration 60
python scripts/electromagnetic_device_simulator.py --command mode --values 0 --sequence 1 --duration 30
```

连续手动运行发送控制时递增 `--sequence`，否则同一接收超时窗口中的重复计数会被拒绝。设备实际联调使用 `--bind-ip 192.168.64.8 --display-ip 192.168.64.4`，配置和防火墙应与固定端口一致。

新增 `electromagnetic_protocol_test` QTest 目标，随 `DISPCTRL_BUILD_TESTS=ON` 启用，覆盖帧字节、校验拒绝、控制范围、字段偏移、WGS84 高度与 MTU 边界。工程编译、QTest 执行和带显控进程的 UDP/UI 联调由本地构建验证；模拟脚本的离线自检不代表 C++ 模块运行验证。

`electromagnetic_reporting_test` 覆盖公共入口合并、原始帧不触发发送、手动订阅、自动切换、消批与检测单次选择。测试不启动 UDP 工作线程。

## 本地调试日志

复用主程序 UTF-8 滚动日志，在**程序当前工作目录**查找 `disp_ctrl_log_0.txt` 到 `disp_ctrl_log_4.txt`，每卷 10 MB，循环覆盖；写入失败时回退到系统临时目录。不是 `disp_ctrl_log.txt`。全局日志级别需要允许 INFO（默认）；WARNING 为错误/拒绝。过滤 `[电磁设备]` 或 `[TestDetection]` 即可，不改变旧指控/激光的日志设置。

- `INIT / CONFIG / WIRE / UDP`：实际加载的配置路径、双方端点和 ID、许可/自动开关、周期与绑定结果。关闭功能也记录 `enabled=false`。
- `ORIGIN / ORIGIN_TEST`：真实 DD05 与临时测试原点的来源/优先级，不把测试位置当实测位置。
- `MANUAL_TRACK / MANUAL_DET / MODE`：人工选择、停止、失败原因和开关切换；`QUEUED` 只表示入队，UDP 未就绪时仍须等待。
- `DET_QUEUE / TRACK_QUEUE / TRACK_REMOVE`：采样记录来源 `REAL/TEST`、批号、生命周期状态、手动/自动模式、RAE、速度、识别结果与编码后的经纬高；航迹附 CPI、UTC/纳秒、幅度/SNR、空间速度/加速度，检测附统计 SNR、波束、通道与置信度。关闭采样不关闭人工操作、异常和摘要日志。
- `TX_DONE / TX_FAIL`：报文计数范围、包数、本机套接字成功/失败及耗时；成功**不是**设备接收应答。
- `LINK`：只在本机网口、对端网络、UDP、协议接收、原点或数据源状态变化时记录。
- `SUMMARY`：累计公共点输入、测试字段登记、入队/消批、实际套接字发包、失败/拒绝/溢出、待发与缓存数、等待 UDP/在途批次的次数、最大发送耗时、编号 5/6/7/9 组包数量。`trackUpserts` 是合并前入队次数，不是实际发出目标数；`msg5..9` 是交给发送线程的组包数。
- `RX / RX_REJECT / RX_SEQUENCE / RX_TRANSPORT_REJECT`：接受/忽略控制、协议校验失败、重复乱序、实际源 IP/端口与配置不一致或数据报无效。

拒绝原因区分 `NO_VALID_ORIGIN`、`DETECTION_METADATA_EXPIRED_OR_MISSING`、`TRACK_METADATA_MISSING`、`TRACK_SAMPLE_MISMATCH`、`INVALID_VALUE_OR_COORDINATE`、`REPORT_DISABLED` 和 `QUEUE_FULL`。异常按固定类别分别限频 5 秒，各类互不遮蔽；下次同类异常写入时带 `suppressedSinceLast`，累计拒绝仍逐次计数。正常目标和发送完成按间隔采样，不逐点打印，不将周期摘要追加到显控 UI 日志栏。

排查顺序：确认 `CONFIG` 配置文件和开关 → `UDP` 绑定 → `SUMMARY` 输入是否增加 → `ORIGIN` 是否有效 → `MANUAL_*` 或 `MODE` 是否选择发送 → `*_QUEUE` 编码值 → `TX_DONE` → 模拟端实际收包。生成测试点迹只发新的专用测试原点通知，不改旧总控测试原点状态。电磁功能/UI 关闭时 PPI 右键委托原处理链路；同时选择旧链路和电磁链路时标签保留旧状态文字。
