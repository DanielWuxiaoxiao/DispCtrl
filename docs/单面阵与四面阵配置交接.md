# 单面阵与四面阵配置交接

适用版本 V8.5.0。本文覆盖显控与资源调度间的阵面位置、机扫归北、系统校时和 BIT 上报。对端按 2026-11-16 更新协议对齐，其中机扫 `DE02` 码盘字段和 `AA03` 有符号偏差按本文口径联调。

## 1. 选择系统和启动模式

在实际加载的 `config.toml` 中修改现有配置段，保存后重启。主 P 显左上方的入口按配置显示「单面阵配置」或「四面阵配置」。两种界面主题使用相同操作和协议逻辑。

| 配置项 | 取值和用途 |
| --- | --- |
| `[displayConfig].default_panel_count` | `1` 为机扫单面阵，`4` 为四面阵。代码以 `>1` 进入多阵面配置，窗口固定展示 ID 0～3。运行时阵面开关不改变系统类型。 |
| `[radar].gps_mode` | 仅用于单面阵启动，`manual` 是默认，显式设置 `auto` 可开机进入自动 GPS。 |
| `[radar]` 的 `longitude`、`latitude`、`altitude`、`azimuth`、`pitch`、`roll` | 参考位置和姿态默认值。高程为海拔米，其余为度。`azimuth` 是配置中的偏航键。 |

## 2. 单面阵（机扫）

窗口中的「工作方式」可在手动 GPS 与自动 GPS 间即时切换，只影响本次运行。切换保留当前编辑草稿，且无需发送位置或校时指令。切到手动时保持当前有效参考，隐藏 D 曲线、设备 GPS 下发及校时按钮，窗口随内容缩小。切回自动会解除单面阵本地覆盖，恢复使用自动参考。各操作结果在原窗口显示，窗口由「关闭」按钮或标题栏关闭。

| 按钮 | 手动 GPS | 自动 GPS |
| --- | --- | --- |
| 位置主按钮 | 「确定下发」使用表格位置和姿态发送 ID 0 的 `AA08`，同时更新显控本地参考。 | 「应用本地」使用表格值更新本次运行参考。电磁启用时也设置其手动位置覆盖。此操作无 `AA08`。 |
| 保存本地 | 写入 `config.toml` 的位置和姿态默认值，同时应用本地，适合保存下次启动位置。 | 电磁未启用时可用，仍为写配置并应用本地。保存动作无 `AA08`，也不修改 `gps_mode`。 |
| 下发 GPS 位置 | 隐藏。 | 从 ID 0 最新可用的 `DE02` 取滤波后的经纬高及同帧北斗航向、倾角、横滚，发送 `AA08`。表格草稿不参与发包。 |
| 解除本地覆盖 | 隐藏。 | 电磁启用时显示，清除显控和电磁的本地覆盖，恢复自动数据源，GPS 模式保持自动。 |
| 下发伺服归北 | 单次发送 `AA03`，偏差 `D = 0`。 | 单次发送 `AA03`，使用点击时最新一帧的有效 D。该帧无有效 D 时要求先检查上报。 |
| 系统校时 | 隐藏。显控不发 `AA10`，资源调度按手动流程使用本地时间。 | 使用 GPS 所在 ID 0 发送 `AA10`，等待 `DE03`。 |

电磁启用时单面阵表格提供经纬高和偏航编辑，倾角、横滚沿用当前参考。自动 GPS 经常规位置合法性、全零及偏离检查后参与滑动平均。首个有效新版位置前，旧 `DD05` 可作为显示参考的兼容来源。手动模式继续接收健康与 GPS 上报并缓存有效自动位置，收到数据不会接管本地手动参考。旧 39 字节 `DE02` 可更新健康状态，需要新版扩展帧才能获得 D 和设备 GPS 下发数据。

### 自动 GPS 归北操作

1. 确认最新 ID 0 的 `DE02` 提供北斗航向 `J0` 与伺服码盘 `A0`，两者按各自 BIT 正常标志和角度范围校验。
2. 观察近 200 次上报的原始 D 曲线。当前公式为 **`D = A0 − J0`**。D 保留正负号和原始差值，曲线遇无效样本断线，无平均或角度归一化。操作员判断稳定后再点击归北。
3. 核对 `[AA03][SUBMIT]` 的角度和 `raw`，再查资源调度收包与伺服执行结果。机扫自动模式的主界面归北快捷入口先打开配置窗口。配置窗口归北按钮发单条 `AA03`，手动模式的主界面旧快捷入口仍保留归北后延时寻位的操作。

## 3. 四面阵

1. 从「四面阵配置」进入，界面阵面 1～4 对应报文 ID 0～3。启动时各行锁定，读取与 `config.toml` 同目录的 `radar_panel_reference.toml` 作为已保存参考。
2. 点击某行「解除锁定」采集该 ID 的 `DE02`，其他行保持或回到锁定。解锁行只读，表格实时展示该 ID 的均值。锁定后冻结当前参考并允许编辑。健康状态与接收时刻仍可更新。
3. 每个 ID 分别保留最近 100 次已采集样本，不足 100 次按实际样本数。经纬高、倾角、横滚取算术平均，偏航取圆周平均。该采集模式允许零值、越界值和突变值进入均值。曲线原始线绘制每次采集的新偏航，均值线使用该次更新后的表格偏航均值。切换 ID 时保留各自均值窗口，曲线继续追加。最终编辑及发包仍校验参数范围。
4. 复核四行后点击「确定下发」，提交一条包含 ID 0～3 的 `AA08`，并保存实际发出的四行。锁定或解锁仅操作本地参考，写入失败会提示。点击「取消」放弃未提交的编辑。ID 0 始终是主界面和统一目标解算使用的参考阵面。
5. 校时选择安装 GPS 的阵面，再点击「系统校时」。软件发送该 ID 的 `AA10`，等待 `DE03`。校时选择独立于当前解锁行。

## 4. 报文核对

长度均区分负载与完整 UDP 帧，偏移从 0 起算。消息 ID 位于各自独立负载的偏移 0。沿用现有 14 字节帧头、5 字节帧尾和小端编码。

| 消息 | 方向 | 负载 / 完整帧 | 联调字段 |
| --- | --- | --- | --- |
| `DE02` BIT | 资源调度 → 显控 | `103 / 122` 字节。机扫兼容旧 `39 / 58` 字节。 | ID 在负载偏移 17。新版纬度、经度、高程、航向、倾角、横滚依次位于 39、47、55、59、63、67。码盘紧接横滚，负载偏移 69（整帧 83），`uint32`、0.001°/码。新旧 103 字节布局等长，上游必须填写以前预留区的这 4 字节。 |
| `AA08` 位置 | 显控 → 资源调度 | `142 / 161` 字节 | 消息 ID 后是四条各 31 字节记录，末尾预留 16 字节。纬度在经度前，各用 `int64`、1e-9°/码。高程 0.01 m/码，航向及倾角 0.001°/码，横滚 0.01°/码。机扫只填 ID 0 的数值，ID 1～3 保留编号、数值填零，资源调度只应用 ID 0。 |
| `AA03` 伺服 | 显控 → 资源调度 | `13 / 32` 字节 | 归北指令 `cmd = 3`。D 紧接方位角，负载偏移 6（整帧 20），`int32`、0.001°/码，负值按有符号小端发送。D = −1.000° 时原始值为 −1000，字节为 `18 FC FF FF`。 |
| `AA10` 校时 | 显控 → 资源调度 | `6 / 25` 字节 | 负载偏移 2 的校时标志为 `1`，偏移 3 是 GPS 所在雷达 ID。ID 0 的负载为 `10 AA 01 00 00 00`。 |
| `DE03` 校时回执 | 资源调度 → 显控 | `6 / 25` 字节 | 负载偏移 2 为结果，`0` 失败、`1` 成功。无请求流水号，窗口显示最近有效回执。等待期间禁用重复提交，10 秒后显示超时并允许再试。 |

校时结果由窗口文字和颜色表示。`AA08` 界面的「已提交」表示显控已提交下发请求，资源调度是否应用位置需查其控制表。`AA03` 的「已提交」也只表示本机提交，归北结果由资源调度和伺服侧确认。

## 5. 现场验收

- **单面阵手动**。开机确认默认工作方式为手动。修改经纬高和偏航后验证本地地图参考、`AA08` 仅应用 ID 0、`AA03` 的 D 为零。点击「保存本地」后重启核对值，检查保存操作未发 `AA08`。
- **单面阵自动**。核对 ID 0 的 `DE02`、BIT 标志和码盘偏移，至少用一组负偏差验证 `A0 − J0` 和 `AA03` 字节。验证切换不触发发包、设备 GPS 下发采用上报而非草稿、校时成功及超时显示。
- **四面阵**。逐一解锁采样，核对 ID、原始偏航及同一时刻的表格和曲线均值。下发后核对四条位置记录，重启验证本地恢复。用接有 GPS 的阵面验证 `AA10` 的 ID 与 `DE03` 结果。

排查时查 `[PANEL_REFERENCE]`、`[RADAR_REFERENCE]`、`[AA08]`、`[AA03]`、`[AA10]` 和 `[DE03]`。四面阵均值可用 `[radar].reference_debug_log_enabled`、`reference_debug_log_interval_ms`、`reference_debug_log_samples` 控制文件日志。验证资源调度确实采用位置、执行归北或完成校时，需要对应的收包或现场记录。
