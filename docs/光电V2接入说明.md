# 光电 V2.0 接入说明

依据《光电设备接口控制文件V2.0》实现，代码位于 `PhotoelectricV2/`。本显控是系统指控端，不是光电厂商的转发终端；旧 `Disp2PhotoManager` 与 9009 `LaserReportManager` 不参与 V2 编解码。

## 启用

在**实际运行目录加载的** `config.toml` 中设置：

```toml
[laser]
enabled = false

[photoelectric_v2]
enabled = true
local_ip = "192.168.101.14"
peer_ip = "192.168.101.10"
target_port = 10100
status_port = 11100
control_local_port = 10101
control_port = 21001
device_id = 1
terminal_id = 0
```

其余参数见仓库配置。网络、端口、ID 修改后重启生效。目标接收端口可选 10100/10200/10300，状态接收端口可选 11100/11200/11300；程序也允许现场指定其它合法端口。对端需将上报目的 IP 改为 `local_ip`，不是继续使用文档中的示例 172.16.0.122。`control_local_port=10101` 是文档未规定的本机发送源端口，独立于 10100 接收端口，可配置；对端控制目的端口默认 21001。

`peer_target_port/peer_status_port=0` 仅表示不限制对端**源端口**；对端 IP、固定帧长、设备 ID、版本、组网模式和校验仍严格检查。`terminal_id=0` 表示直接连接，无厂商终端；非零时接收也校验该 ID。

同时打开 V2 和 9009 时记录 `PE-V2 CONFIG CONFLICT`，仅启用 V2；旧 `system.enable_photoelectric_tx` 也被 V2 隔离。两个功能都关闭时不显示 F6 入口，不检测它们的 IP。V2 配置错误不会偷偷改用 9009 或随机源端口。

## 界面

- PPI **光电V2 (F6)**：输入普通航迹批号，持续引导当前目标。普通航迹点/标签右键支持下发与停止。
- PPI **光电V2控制**：查看对端状态、目标表和 8 项设备控制；每次确认按全部 8 项配置发一帧，不把未选项理解为“不修改”。运动停止需主动下发“停止”；窗口关闭不额外发指令。
- 控制窗口可开启全部当前普通航迹自动引导。自动开启时它优先于单目标选择；停止手动引导不会关闭自动模式。
- 健康页显示 V2 专属本机 IP、对端 ICMP 和 UDP/目标/状态/终端心跳接收情况。点击协议状态条打开控制窗口。IP 可达、UDP 本机发送成功均不代表设备已执行；本协议没有控制应答。
- 收到的光电目标保留在独立有界表中，不冒充雷达普通航迹、不反向触发其它设备上报。超时目标明确标记“超时”，设备未上报不显示为默认正常。

## 线上格式

全为小端；长度包含版本号、帧头、长度字段、校验字。校验按文档“各字节相加与 0xFF”解释为**校验字之前所有字节累加取低 8 位**，不是 XOR，也不是总和补到 0xFF。合作方若对“奇校验”另有解释，需用实际抓包确认后统一，不能同时宽松接受多个算法。

| 方向 | 功能 | 总字节 |
|---|---|---:|
| 显控→光电 | 0x3400 经纬高引导 | 47 |
| 显控→光电 | 0x3500 设备控制 | 34 |
| 光电→显控 | 0x3200 目标 | 60 |
| 光电→显控 | 0x3000 状态 | 43 |
| 光电终端→显控 | 0x3100 心跳 | 22 |

`0x3200` 按该文档逐字段相加为 60 字节，不能与电磁设备的 64 字节检测点记录混用。无终端时不要求凭空收到 0x3100；程序作为系统指控只接收该心跳，不冒充光电厂商终端发送它。旧 0x0100/0x3401 不属于此版本。

引导经纬度使用 double 解算后量化为 `uint32 × 1e-5°`；高度为 `uint16(海拔+500 m)`，速度为现有雷达径向速度的绝对值（无符号 m/s，并非额外估计的三维速度），来源属性固定 `0=雷达探测数据`，与无人机分类无关。按附件全部无符号定义，负经纬度、海拔低于 -500 m 或超过 65035 m、速度超出 65535 m/s 拒绝编码，不能暗中改成补码。需要南/西半球或有符号速度时应先修改双方协议。

雷达原点使用真实 DD05，收到 DD05 前可使用完整有效的 `[radar].longitude/latitude/altitude`。与旧链路共享 `Basic/wgs84coordinate.h`：RAE→ENU→WGS84，高度为原点海拔加 RAE 垂直分量；不额外叠加阵面偏航/倾角/横滚，不使用电磁模块的临时手动原点。测试航迹同样进入 `traInfoProcess` 并可 F6 下发；检测点、TBD、协同及离线回放不进入此链路。

默认每秒每个选中目标只发最新点；最大缓存由 `max_tracks` 限制，过期/消批停止发送。协议没有消批/撤销字段，不伪造“取消帧”。修改选择后已进入工作线程的一批不能撤回，下一批按新选择发送。

## 线程与调试

UDP 套接字仅在独立线程中创建、绑定、收发和销毁。GUI 保存有界最新点，发送最多一批在途；控制队列最多 16 帧。接收先严格解析，最多合并 256 个目标和最新状态/心跳，每 100 ms 提交一次，最多一批等待 GUI 确认，不允许接收信号无限排队。窗口仅可见时每 500 ms 刷新，关闭不影响协议收发。接收缓冲不保存无限历史。

日志前缀统一 `PE-V2`：配置路径与实际端点/ID、绑定结果、原点切换、选中/停止、设备控制 HEX、引导 HEX 采样、解析字段采样、累计本机发送/接收/拒绝数和超时变化。正常收发与同类异常由 `log_interval_ms` 限频；设备控制操作立即记录。数据超时不反复刷日志。V2 的日志、状态和选择不使用 9009 缓存。

针对性测试：`photoelectric_v2_protocol_test`、`photoelectric_v2_module_test`、`subsystem_feature_flags_test`。覆盖字节偏移/长度/校验、64 位编号、完整字段解析、非法和截断帧、生命周期、缓存/在途上限、原点、超时及配置互斥。完整 Qt 编译、对端实际报文、F6/右键/设备控制和健康页需本机联调，不将静态检查称作实机验收。
