# 光电跟踪下发 / 激光侦察上报 —— 协议与功能说明

> 本文档面向**在其它项目中复刻或对接该功能的开发者（含 AI）**，自包含描述 RadarAPP
> 中“光电跟踪下发”和“激光侦察上报”的三种工作模式、网络拓扑、IP/端口、以及全部
> 涉及的二进制协议结构。所有结构体均 **`#pragma pack(1)`**（紧凑、无填充、小端）。

---

## 1. 总览：三种下发/上报模式

注意这里实际涉及**两个独立的下游系统**：

| # | 模式（UI 右键菜单） | 下游系统 | 触发 | 频率 | 目标数 |
|---|----------------------|----------|------|------|--------|
| 1 | **自动上报**（默认关闭） | 激光控制终端 | 右键“开启自动上报”后持续 | 1 s 周期 | 最多 **10** |
| 2 | **引导光电跟踪(单次)** | 光电转台系统 | 每次点击下发一次 | 单次 | 1 |
| 3 | **引导光电跟踪(持续)** | 光电转台系统 **+** 激光控制终端 | 点击后持续，直到关闭/目标消批 | 1 s 周期 | 1 |

要点：
- **“光电跟踪下发”**（模式 2/3）= 把目标的位置/速度送给**光电转台**做引导（伺服指向），协议为 `PhotoElectricParamSet` / `PhotoElectricParamSet2`。
- **“激光侦察上报”**（模式 1 自动 / 模式 3 单目标）= 把当前航迹点打包成**侦察帧**送给**激光控制终端**，协议为 `LaserReconData + N×LaserTargetInfo`。
- 模式 3“持续”同时做两件事：① 持续给光电转台下发引导；② 把该单一目标作为侦察帧上报激光端。
- 另有“**手动跟踪**”菜单项：仅向**数据处理分系统**下发 `SetTrackManual`，**不触发任何光电/激光下发**。
- 两条上报路径互相独立：自动上报开启时优先走 10 目标自动上报；否则走单目标（光电跟踪）上报。**默认全部关闭**。

## 2. 网络拓扑（IP / 端口）

### 2.1 光电转台系统（模式 2/3 的引导下发）
| 角色 | IP | 端口 | 说明 |
|------|----|------|------|
| 显控端本地绑定（面向光电） | `192.168.101.14` (`DISP_CTRL_IP_FOR_PHOTO`) | `10100` (`DISP_2_PHOTO_PORT`) | 发送源 |
| 光电系统（接收） | `192.168.101.10` (`PHOTO_ELE_IP`) | `21001` (`PHOTO_GET_DISP_PORT`) | 引导指令目的地 |

> 备注：工程注释指出实际光电信息最终由部署在某 Ubuntu 服务器（`192.168.64.3`）上的光电系统软件接收。
> 显控→光电通道开启心跳（`HeartbeatPacket`，功能号 `0x0100`，1 s）。

### 2.2 激光控制终端（模式 1/3 的侦察上报）
| 角色 | IP | 端口 | 说明 |
|------|----|------|------|
| 雷达端（本地绑定，收发共用） | `192.168.101.9` (`RADAR_LASER_IP`) | `9009` (`LASER_UDP_PORT`) | 单端口双向 UDP |
| 激光控制终端 | `192.168.101.10` (`LASER_CTRL_IP`) | `9009` | 侦察帧/状态帧目的地 |

设备 ID：雷达端 `RADAR_DEVICE_ID = 2100`（210X），激光端 `LASER_DEVICE_ID = 5100`（510X）。

### 2.3 手动跟踪（下发数据处理分系统）
| 角色 | IP | 端口 |
|------|----|------|
| 显控端本地绑定 | `192.168.80.4` (`DISP_CTRL_IP`) | `6008` (`DISP_2_DATA`) |
| 数据处理（接收） | `192.168.80.64` (`DATA_PRO_IP`) | `8008` (`DATA_GET_DISP`) |

## 3. 光电引导协议（模式 2/3 → 光电转台）

两种等价下发结构，运行时由 `photoParamType` 选择其一（0=经纬高，1=方位俯仰距离）。
公共帧头常量：`head = 0x7D6D5D4C`，`versionNumber = 0x01`，`checkCode` 为异或校验
（覆盖范围：从 `versionNumber` 之后到 `checkCode` 之前，即不含版本号/帧头/dataLen/checkCode 自身——
见 `dataLen` 计算式）。`timeStamp` 发送时填 `QDateTime::currentMSecsSinceEpoch()`。

### 3.1 `PhotoElectricParamSet`（functionNum = `0x3400`，经纬高方式）
| 字段 | 类型 | 说明 |
|------|------|------|
| versionNumber | uint8 | 0x01 |
| head | uint32 | 0x7D6D5D4C |
| dataLen | uint16 | = sizeof(结构) − version − head − dataLen − checkCode |
| functionNum | uint16 | 0x3400 |
| deviceNum | uint32 | 设备编号 |
| endDeviceNum | uint32 | 终端编号 |
| timeStamp | uint64 | 毫秒时间戳 |
| targetNum | uint64 | 引导目标编号（批号） |
| lon | uint32 | 经度 ×100000 |
| lat | uint32 | 纬度 ×100000 |
| alt | uint16 | 高度（m），代码中 = 目标高度 + 500 |
| speed | int16 | 速度 |
| targetType | uint8 | 目标类型 |
| checkCode | int8 | 异或校验 |

### 3.2 `PhotoElectricParamSet2`（functionNum = `0x3401`，方位/俯仰/距离方式）
与 3.1 帧头一致，差异字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| a | float | 方位角 0~360° |
| e | float | 俯仰角 −90~+90° |
| r | uint16 | 距离 m |
| speed | int16 | 速度 |
| targetType | uint8 | 目标类型 |

> 模式 2（单次）与模式 3（持续）下发的结构完全相同，区别只在**触发次数**：
> 单次=点击发一帧；持续=每次该批号航迹更新（约 1 s）就发一帧，直到关闭或目标消批。

## 4. 激光侦察上报协议（模式 1/3 → 激光控制终端）

### 4.1 通用帧结构
完整帧 = **`LaserFrameHeader`(20) + 数据内容(n) + `LaserFrameTail`(4)** = 24+n 字节。

`LaserFrameHeader`（20 字节）：
| 字段 | 类型 | 值/说明 |
|------|------|---------|
| frameHead[2] | uint8×2 | `0xEB 0x90` |
| frameType | uint16 | 侦察帧 = `0x0300` (`LASER_FT_RECON`)；状态帧 `0x0200`；控制响应 `0x0101` |
| senderID | uint16 | 2100（雷达） |
| receiverID | uint16 | 5100（激光端） |
| timeStamp | `LaserDataTime`(8) | 见 4.4 |
| dataLen | uint16 | 数据内容域字节数 n |

`LaserFrameTail`（4 字节）：
| 字段 | 类型 | 说明 |
|------|------|------|
| checkSum | uint16 | 从 `frameType` 起到数据内容止，按字节累加取低 16 位 |
| frameTail[2] | uint8×2 | `0x4C 0x5A` |

### 4.2 侦察数据内容 = `LaserReconData`(12) + targetCount × `LaserTargetInfo`(64)

`LaserReconData`（12 字节，固定部分）：
| 字段 | 类型 | 说明 |
|------|------|------|
| typeID | uint16 | 1 = 雷达侦察结果 |
| contentLen | uint32 | 侦察数据域字节数 |
| dataSeq | uint32 | 侦察序号，递增 |
| targetCount | uint16 | 目标数 N，**最大 10**；无目标时为 0（仍发空侦察帧） |

`LaserTargetInfo`（64 字节，每目标一个）：
| 字段 | 类型 | 说明 |
|------|------|------|
| batchID | uint32 | 目标批号 |
| targetTime | `LaserDataTime`(8) | 该航迹点时间 |
| distance | float | 距离 m |
| azimuth | float | 方位角 [0,360)，正北 0，顺时针增 |
| elevation | float | 俯仰角 [−90,90]，水平 0，向上正 |
| speed | float | 速度 m/s |
| azimuthSpeed | float | 方位角速度 °/s（当前填 0） |
| elevationSpeed | float | 俯仰角速度 °/s（当前填 0） |
| radialSpeed | float | 径向速度 m/s，接近为正（当前=speed） |
| cancelFlag | uint8 | 0 正常 / 1 消批 |
| targetType | uint16 | 见 4.3 映射 |
| trackQuality | uint16 | 0~7，越大越好 |
| reserved[19] | uint8×19 | 保留 |

### 4.3 目标类型映射（雷达分类 → 激光协议类型）
雷达分类 `batchClasses`：0 未知 / 1 无人机 / 2 行人 / 3 车辆 / 4 鸟 / 5 其它
激光协议类型：0 普通 / 1 无人机 / 2 假目标 / 3 鸟 / 4 其他

| 雷达 | → 激光 |
|------|--------|
| 0 未知 | 0 普通 |
| 1 无人机 | 1 无人机 |
| 2 行人 | 4 其他 |
| 3 车辆 | 4 其他 |
| 4 鸟 | 3 鸟 |
| 5 其它 | 4 其他 |

航迹质量按 `statMethod`：0（滤波）→7；1（外推）→3；其它→0。

### 4.4 `LaserDataTime`（8 字节时标）
| 字段 | 类型 | 范围 |
|------|------|------|
| year | uint8 | 年份后两位 [0,99] |
| month | uint8 | [1,12] |
| day | uint8 | [1,31] |
| hour | uint8 | [0,24) |
| minute | uint8 | [0,59] |
| second | uint8 | [0,59] |
| msecond | uint16 | [0,999] |

### 4.5 上报节奏
- 雷达端 1 s 周期上报：**状态帧**（`0x0200`，隐含心跳）+ **侦察帧**（`0x0300`）。
  常量 `LASER_REPORT_INTERVAL = 1000`。
- 侦察帧内容由显控侧 `buildAndSendLaserRecon()` 每 1 s 构建一次，经
  `Controller::sendLaserRecon` 信号交给 laserSocket 缓存后定时发出。

## 5. 手动跟踪协议（→ 数据处理分系统）

`SetTrackManual`（4 字节），外层套显控内部协议帧 `ProtocolFrame` + `ProtocolEnd`：
| 字段 | 类型 | 说明 |
|------|------|------|
| mesID | uint16 | `0xDF01` |
| batchID | uint16 | 目标批号 |

内部帧封装 `packData()`：`ProtocolFrame`(head=`0xFA55FA55`, srcID, destID, commCount, dataLen)
+ 负载 + `ProtocolEnd`(checkCode, end=`0x55FA55FA`)。源 ID `DISP_CTRL_ID=0xBB04`，目的 `DATA_PRO_ID=0xBB03`。

## 6. 触发与状态逻辑（复刻要点）

- 全局状态：
  - `gCurrentPhotoTrackID`（int，-1 表示无）—— 当前“持续光电跟踪”的批号；驱动**单目标侦察上报**。
  - `gAutoLaserReconEnabled`（bool，默认 false）—— **自动上报（10 目标）**总开关。
- **模式 1 自动上报**：`gAutoLaserReconEnabled == true` 时，`buildAndSendLaserRecon` 遍历所有航迹
  `traPoints`，取各批号最新点，最多 10 个。
- **模式 3 持续跟踪**：右键设 `gCurrentPhotoTrackID = 批号`、`ifPhotoTrack=true`，并 `emit setPhotoTrack(...)`；
  之后每次该批号航迹更新都会再 `emit setPhotoTrack`（持续引导光电）。自动上报**关闭**时，
  `buildAndSendLaserRecon` 只上报该单一批号。点击另一个目标的“持续”会先停旧目标再切换。
  **目标消批**：`TraInfo` 析构时若该批号正被跟踪则把 `gCurrentPhotoTrackID` 复位为 -1，停止上报。
- **模式 2 单次跟踪**：仅 `emit setPhotoTrack(...)` 一次，不改全局状态、不进入侦察上报。
- **手动跟踪**：仅 `emit setManual(SetTrackManual)`，与上述全部无关。
- 优先级：自动上报开启 → 走 10 目标分支；否则 → 走单目标分支（若有 `gCurrentPhotoTrackID`）。

## 8. 复刻清单（在新项目落地）

1. 按第 2 节配置三套 IP/端口（光电转台、激光终端、数据处理）。
2. 按第 3/4/5 节定义 `#pragma pack(1)` 结构体，注意字节序为小端、校验算法两套不同
   （光电=异或；激光=帧类型起按字节累加低 16 位）。
3. 实现 1 s 定时器：状态帧 + 侦察帧（激光端）；引导帧（光电端，持续模式）。
4. 维护两个全局开关与“当前持续跟踪批号”，按第 6 节优先级和消批逻辑驱动上报。
5. 默认三种主动上报全部关闭，由 UI 显式开启。
